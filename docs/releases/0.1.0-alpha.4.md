# Release 0.1.0-alpha.4

Version 0.1.0-alpha.4 is a two-stage full-function qualification candidate for
one approved Relution qualification tenant. Its MSI is tenant-fixed, unsigned,
and non-distributable. It does not authorize Relution application uninstall,
administrative, production, signing, or publication operations. MSI uninstall is
used only to clean up candidate verification.

## Compile-time qualification profiles

Every alpha.4 qualification build selects
`APPPORT_QUALIFICATION_PROFILE=read_only` or `write_qualification`.
`APPPORT_RELUTION_WRITES_ENABLED` must exactly match the selected profile.
Release builds also require `APPPORT_QUALIFICATION_TENANT_APPROVED=true` and
`APPPORT_RELUTION_TENANT_CLASS=qualification`.

The write-qualification profile additionally requires
`APPPORT_DISPOSABLE_RESOURCES_APPROVED=true` and an externally supplied,
non-secret qualification plan. The plan is not committed to this repository or
included in release evidence.

## Candidate evidence and pilot qualification

`candidateReady=true` requires a clean source tree, successful source gates, a
Windows MSVC MSI, its SHA-256, validated fixed qualification configuration, a
passing embedded-secret scan, and a passing installed-MSI self-check followed by
MSI uninstall. It records `signed=false` and `distributable=false`.

`pilotQualified=true` is separate evidence: it is recorded only after the
authorized live qualification for the selected profile is complete. It must not
be inferred from `candidateReady`. Any unrun external gate, including
managed-device validation and write qualification when relevant, remains
explicitly unqualified.

## Token handling

Qualification tokens are accepted only from masked console input. They never
appear in arguments, environment variables, files, logs, or reports.

Alpha.3 remains the historical read-only candidate; see the
[alpha.3 release notes](0.1.0-alpha.3.md). See also the
[release status](../../RELEASE_STATUS.md) and
[release checklist](../RELEASE_CHECKLIST.md).
