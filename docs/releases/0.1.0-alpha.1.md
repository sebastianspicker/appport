# Release 0.1.0-alpha.1

Alpha.1 was an early candidate for a limited managed-device pilot. It used a
web service and authentication flow that have since been replaced. This note
records that version; see [release status](../../RELEASE_STATUS.md) for the current
application.

## What it included

- A Windows 11 x64 client with Apps, Updates, and Installed views.
- Browser-based OIDC sign-in with a loopback callback and verifier exchange.
- Device matching and repeated checks of the user's device assignment.
- Permission-filtered catalogs for Winget, Windows MSI, and Windows EXE packages.
- Install and update confirmations, with idempotent action tracking to prevent
  duplicate requests.
- SQLite audit history and an explicit `unknown` state for unresolved outcomes.
- Windows Credential Manager storage, scheduled update checks, and notifications.
- A single-replica broker container with `/data` persistence and file-based
  production secrets.

## Limits of that version

The browser handled sign-in but did not show a software catalog. The broker used
one process and one SQLite database, and the Windows client had no independent
updater. Native sessions were portable bearer tokens. Resolving a Relution user
initially depended on a username claim.

Live writes stayed disabled pending deployment qualification. Portable source
tests did not establish a signed Windows MSI, production container behavior, live
Relution behavior, encrypted restore, or operation in a managed pilot.

For current setup and testing, use the [operations guide](../OPERATIONS.md).
