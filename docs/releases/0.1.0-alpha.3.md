# Release 0.1.0-alpha.3

Alpha.3 introduced an unsigned, read-only test candidate for one approved Relution
tenant. It was not suitable for general distribution. Alpha.4 defines the
[current qualification process](../OPERATIONS.md).

## Build and candidate checks

The build required a tenant origin, organization UUID, and Appport application
UUID approved for testing. These were non-secret inputs. Missing, placeholder,
malformed, or credential-bearing values were rejected.

`APPPORT_RELUTION_WRITES_ENABLED=false` was embedded in the candidate and could not
be changed at runtime.

A `candidateReady=true` result required passing source checks, a Windows MSVC MSI,
its SHA-256 hash, valid embedded configuration, and a passing secret scan of the
artifact. The report also recorded `signed=false` and `distributable=false`.

## Live testing

Device connection, catalog and icon loading, inventory, and background checks
still needed read-only testing on a managed tenant. Deployment and administrative
operations were outside this alpha's scope. Testing permission to make destructive
changes, code signing, and production qualification also remained incomplete.
